--- 做了什麼（30 秒）-------------------------------------------------------
架在 LLM agent 和 5G 核網工具之間的 gateway，三層防禦：
  L1  識別碼 token 化
  L2  taint 追蹤 + gateway 自簽 capability
  L3  rate cap + core 端前置檢查（core_precheck）+ procedure FSM
整套跑在真實 free5GC v4.1.0 + UERANSIM + 9 台 UE 上（不是模擬）。
攻擊由「必定被劫持的腳本化 agent」透過被注入的 alert log 發動。

--- Live 結果（以 SMF 真實狀態為 ground truth，180 次 run）----------------
  L1          : 識別碼外洩 100% -> 0%
  L2 (signed) : DoS 攻擊成功率 0.67 -> 0；DOS-02 偽造 ticket
                從 claim-only 放行 8.4/9 降到 0
  L3 (rate)   : 當 L2 被繞過/設錯時，大量拆除從 9 個壓到 3 個
  成本        : 每次呼叫中位數 0.03-0.11 ms；core precheck 約 13 ms
  誤擋        : 正常單筆操作 0 誤擋；唯一誤擋是合法批次清空（BENIGN-05）
  驗證        : 498 次計入的 release 全部 SMF 204 + 探測 404 雙重確認

--- L3 到底能做什麼（講清楚，別被「只有 offline」誤導）--------------------
L3 有三個子檢查，保護力與驗證狀態不同：

  Rate cap（量上限）：
    * 綁死每個呼叫者（連授權者），L2 失效時把損害壓到 3/60s。
    * LIVE 證明：在「L2 被誤設成接受任何授權字串」這個實際失誤情境下，
      偽造 ticket 的 DoS 仍被壓到 3（DOS-02: 8.4 -> 3）。
    * => L3 在真核網上「確實提供防護」，但只在 L2 失效模式下才啟動；
         L2 正常時 L3 對攻擊是零增量（L2 已先擋）。

  core_precheck（核網真實狀態）：
    * 轉送前自己問 core，擋打向不存在 session 的 release、不信 agent 宣稱。
    * 機制 live 會跑（+13ms），但「擋下」只有 offline（live 目標都真的存在）。

  FSM（順序）：
    * 擋 out-of-state release（重複/亂序）。
    * offline-only；對 free5GC 的 release 冗餘（SMF 本就 404）。

一句話：L3 = 不依賴 secret、綁所有呼叫者的「後備層」。它的 live 價值在
「L2 失效」模式下已證明（rate cap 壓到 3）；完整的必要性論證（即使 L2 正常
也需要 L3 的 capability 濫用、ground-truth 擋下、有害亂序）目前在 offline。

--- Offline 測試：方法與成果 -----------------------------------------------
方法：
  一組 deterministic（可重現）測試，打自寫的假 core，時間用注入的假時鐘，
  所以「慢速」攻擊不用真的等、結果每次一樣。測 live 難以或無法觸發的情況。

成果（全部通過）：
  * FSM 正確性 : 擋 out-of-state release，與時序無關（slow drip 一樣擋）
  * 通用性     : 同引擎用 config 就能守第二個真 3GPP procedure（UE 去註冊）
                 和一個非 5G procedure（門鎖），零改碼 -> 不是三條硬編碼規則
  * Adaptive 邊界 : 量出失效點 —— slow drip 繞得過 rate cap，FSM 順序檢查繞不過
  * 真 capability 濫用 : agent 握 9 次 capability 時，L2 放行、L3 rate cap 壓到 3

要誠實說的一句：
  offline 證明「機制正確、而且通用」，不是「在真 core 上擋下真實危害」
  —— 後者因為假 core 的危害是模擬的，要 live 才算數。

--- 一句話總結 -------------------------------------------------------------
在真實 5G 核網上做出低成本的邊界防禦：live 證明 L1+L2 擋下所有攻擊、開銷
可忽略；L3 是後備層，其 rate cap 在 L2 失效模式下 live 證明能壓制損害，
更完整的必要性論證則以可重現的 offline 測試呈現。
